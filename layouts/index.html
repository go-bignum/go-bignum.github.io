Arbitrary precision, in pure Go.
Correctly rounded, then checked against an oracle.

go-bignum is the arbitrary-precision layer for Go: correctly rounded elementary functions and constants on math/big.Float, at any precision and in all six rounding modes, and the oracle harness that drives mpmath from Go to check them. Each function returns the exact result rounded, and says on which side of it the value lies. No cgo, no dependencies.

Why go-bignum

The MPFR contract, on math/big.

Every function returns the exact result rounded to the receiver's precision in the receiver's rounding mode, so results are reproducible bit for bit on every architecture and every Go version. The conventions are math/big's.

√

Roots

Sqrt, Cbrt, Root(z, x, n) and Hypot, correctly rounded in every mode, which big.Float.Sqrt alone is not.

e

Exponentials and logarithms

Exp, Expm1, Log, Log1p, Log2, Log10 and Pow.

π

Trigonometric and hyperbolic

The six trigonometric functions and their inverses, and the six hyperbolic ones; argument reduction is exact for any argument.

γ

Constants

Pi, E, Ln2, Ln10 and EulerGamma, at any precision.

🎯

Rigorous by construction

Every approximation is an enclosure (midpoint-radius balls, fixed-point series with bounded error), evaluated by Ziv's strategy: raise the working precision until the enclosure rounds to a single value.

🧪

An oracle for the fleet

The oracle package drives mpmath from Go, or uses bigfloat itself as the reference, and stores correctly rounded results as golden fixtures other packages can check against.

📦

Pure Go, CGO=0

No cgo, no dependencies. Trigonometric arguments, the Ziv loop and exact roots and powers are bounded, so untrusted input cannot run a function unbounded.

⚖️

BSD-3-Clause

Every repository of the organization. mpmath is an oracle only; MPFR was a reference for the contract, not for code.
